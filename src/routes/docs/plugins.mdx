# Writing Plugins

Zenkai can be extended with **Lua 5.4** scripts. Put a folder with a `manifest.json` and a `main.lua` into one of the plugin directories and Zenkai picks it up automatically.

New to this? Start with the step-by-step [Your First Plugin](/docs/first-plugin) tutorial.

## Directory structure

```
my-plugin/
  manifest.json
  main.lua
```

Zenkai looks for plugins in these places, in order:

The first match wins: if two plugins share a name, the later one is skipped.

Plugins are discovered and started after the result list first appears, so they never slow down startup. If you type before that, they're started before your query is handled, so no results are lost.

Include `version`, `description`, `author` and `disabled` even when you don't need them: Zenkai 1.4 refuses manifests that leave any of them out.

### Lazy loading

With `activation_prefixes`, Zenkai reads the manifest at startup but doesn't load your Lua script or its config until a query starts with one of the prefixes. Matching ignores case but is otherwise literal: `run:` matches `RUN: echo hi` but not `run`.

Once activated, the plugin stays loaded until Zenkai exits. Its `on_startup` runs once, right before its first query. Other hooks only start firing after activation, so leave this field out if your plugin needs lifecycle events from the start. Plugins that never activate don't get `on_close` or `on_shutdown`.

## Hooks

Hooks are global Lua functions in `main.lua`. Zenkai checks which ones exist and only calls those.

### `on_query(query)`

Called whenever the search text changes. Add results with `api.add_result()`.

```lua
function on_query(query)
  if query == "ping" then
    api.add_result("Pong!", "it works", "face-smile", "NoReturn")
  end
end
```

### `on_open(id)`

Called when the user presses Enter on one of your results. `id` is the value `api.add_result()` returned. It fires for both result types; `"NoReturn"` just keeps Zenkai open afterwards.

### `on_action(result_id, action_id)`

Called when the user picks one of your actions from the **Ctrl+K** menu. Register actions with `api.add_action()` in `on_query`.

```lua
function on_query(query)
  local id = api.add_result("Example", "Description", "edit-copy", "NoReturn")
  api.add_action(id, "Copy Value", 1, "edit-copy")
end

function on_action(result_id, action_id)
  if action_id == 1 then api.copy_text("Value") end
end
```

Actions keep Zenkai open unless the hook calls `api.close()`.

### `on_startup()`

Called once after the plugin is loaded. Use it for one-time setup.

### `on_shutdown()`

Called when Zenkai exits. Use it to save state.

### `on_close()`

Called when the launcher window closes (Escape, opening a result, or clicking away).

### `on_keypress(key)`

Called on every key press with the key name, e.g. `"F1"`, `"Return"`, `"Escape"` or `"Tab"`.

### `on_idle()`

Called when Zenkai is idle, and when an `api.http_get` request finishes. A good place to call `api.set_query` to refresh results.

### `on_results(results)`

Called with the full result list just before it's shown. Each entry has `title`, `subtitle`, `icon` and `result_type`.

## Plugin config

Zenkai reads `<config folder>/<plugin name>.json` (for example `~/.config/zenkai/my-plugin.json`), falling back to `config.json` next to `main.lua`, and hands it to your script as the global `plugin_config` table. Ship a `config.example.json` for users to copy.

The file has a fixed shape. Unknown keys make the whole file invalid (the error shows up in `--debug` output):

```json
{
  "commands": [
    { "title": "Required", "subtitle": "optional", "icon": "optional", "url": "optional", "text": "optional", "exec": "optional" }
  ],
  "replace": false,
  "roots": ["~/Workspace"],
  "exclude": ["node_modules"],
  "include_hidden": false
}
```

Every key is optional except `title` inside each command. Most plugins only need `commands`: a list of entries your script turns into results.

## Sandbox

Plugins run in a restricted Lua environment. These globals are removed:

<Table>
  <tr>
    <Th>Global</Th>
    <Th>Why</Th>
  </tr>
  <tr>
    <Td>`os`, `io`</Td>
    <TdDesc>Direct OS and filesystem access. Use the `api` functions instead.</TdDesc>
  </tr>
  <tr>
    <Td>`load`, `loadstring`, `loadfile`, `dofile`</Td>
    <TdDesc>Running code from strings or files</TdDesc>
  </tr>
  <tr>
    <Td>`require`, `package`</Td>
    <TdDesc>Loading modules</TdDesc>
  </tr>
  <tr>
    <Td>`debug`</Td>
    <TdDesc>Introspection and debug hooks</TdDesc>
  </tr>
</Table>

`string`, `table`, `math`, `utf8`, `coroutine`, `pcall` and `xpcall` are all available.

Each hook call may run at most **50,000 Lua instructions**. A plugin that goes over is stopped with `"plugin exceeded instruction limit"`, so a runaway loop can't freeze Zenkai.

## Example: a word counter

```lua
-- manifest.json: { "name": "wordcount", "main": "main.lua", "activation_prefixes": ["wc:"] }

local last_count = nil

function on_query(query)
  local text = query:match("^[wW][cC]:%s*(.*)$")
  if not text or text == "" then return end

  local words = 0
  for _ in text:gmatch("%S+") do words = words + 1 end
  last_count = tostring(words)

  local id = api.add_result(words .. " words", #text .. " characters", "accessories-text-editor", "NoReturn")
  api.add_action(id, "Copy and Close", 1, "edit-copy")
end

-- Enter copies the count and keeps Zenkai open
function on_open(id)
  if last_count then api.copy_text(last_count) end
end

-- Ctrl+K → "Copy and Close"
function on_action(result_id, action_id)
  if action_id == 1 and last_count then
    api.copy_text(last_count)
    api.close()
  end
end
```

For bigger examples, read the bundled plugins in `external/plugins/`: `calculator`, `files`, `quicklinks`, `snippets` and `url`.

## Loading plugins

```bash
# Load everything (default)
zenkai

# Only specific plugins
zenkai --plugin=calculator --plugin=files

# No plugins at all
zenkai --no-plugins

# Plugins only, no apps
zenkai --no-dapps --plugin=calculator
```

## Tips

1. **Check the logs:** `zenkai --debug` shows `api.log()` and `print()` output and any Lua errors.
2. **Keep `on_query` fast:** it runs on every keystroke. Cache work, and use `api.http_get` plus `on_idle` for anything slow.
3. **Use a prefix:** `activation_prefixes` keeps your plugin from costing anything until it's needed.
4. **Test in isolation:** `--plugin=<name>` loads only your plugin.
5. **Icon names** come from the system icon theme. Common freedesktop names like `"face-smile"` and `"system-search"` are the safest bet.
